01 / HomeProduct tourStandard access

Start with what the network is doing.

Standard access · Open the explorer and follow live activity without signing in.

Home / overview

Network at a glance

  • Current base fee and average gas per block over the last minute.
  • Recent network-usage and base-fee charts with time-based hover details.
  • Sync status and delay warnings explain how current the displayed data is.
Home / live feed

A live starting point

  • Latest blocks link directly to their transactions and metrics.
  • Most-active-wallet cards show transaction volume, gas use, and fees.
  • Automatic updates, a block-progress animation, and connection / retry messages.
In practiceThis tour covers standard features first (1–12), then administrator features (13–18). Allow roughly 10 minutes.

02 / SearchProduct tourStandard access

Find the block, transaction, or entity.

Paste the identifier you already have. Search suggestions lead into the relevant detail page.

One search entry point

What you can search

  • Block numbers and stored block hashes.
  • Transaction hashes and entity keys.
  • Addresses known as senders, balance accounts, or indexed entity owners / creators.
Suggestions + results

Ways to navigate

  • Use full identifiers or hex prefixes of at least six digits, with or without 0x.
  • Select a suggestion or use the Search page to review matching result types.
  • Open an address directly even when it has no indexed search match.
In practiceUse Search for identifiers. Use the Data page for attribute conditions such as “status is active.”

Source: OmniSearch.tsx · SearchView.tsx · omni-search.md

Open this view ↗
Presenter. Demonstrate a block number and a shortened identifier. Search is not a general text search: it does not search payload contents, attribute text, or log topics. The optional entity index expands the identifier coverage to projected owners, creators, and entity keys.
03 / BlocksProduct tourStandard access

Inspect a block from the outside in.

Start with a filtered list, then open a block to see its metrics and every stored transaction.

Blocks

Blocks list

  • Filter by block-number bounds and date / time bounds; choose the row limit.
  • Compare block time, transaction count, base fee, burnt fees, and gas usage.
  • See input-data sizes and average transaction metrics; copy a link to the filtered view.
Block

Block details

  • Enter a block number or move to the previous / next block.
  • Inspect timing, fees, gas, rewards, data sizes, and available batcher metrics.
  • Open transactions, senders, and decoded Arkiv operations from the block’s transaction table.
In practiceUse this view to explain a fee spike, a full block, an empty block, or an unusual batch of transactions.

04 / AddressesProduct tourStandard access

Follow an address through its transactions.

The Address view narrows transaction history to the sender, block interval, nonce range, or dates that matter.

Filters + paging

Narrow the history

  • Filter by sender address, an exact block, or lower / upper block bounds.
  • Add nonce bounds and date bounds to isolate a sequence of submissions.
  • Choose the page size, jump to a page, and switch result order.
Transaction list

Compare each transaction

  • Read block, hash, nonce, and the summary of Arkiv operations.
  • Compare gas used / limit, input size, compressed input size, effective fee, and total fee.
  • Follow links to the full transaction, its block, or another address; share the filtered URL.
In practiceAn address filter shows transactions sent by that address. It is not a complete account-transfer ledger.

05 / TransactionsProduct tourStandard access

Understand what a transaction did.

A transaction detail page combines execution outcome, cost, and decoded Arkiv actions.

Transaction overview

Execution and cost

  • Success / failure, block and position, timestamp, sender, recipient or created contract.
  • Transaction type, nonce, transferred value, gas limit, gas used, and input sizes.
  • Base, effective, priority, and total fees; copy identifiers and open the external decoder.
Operations + references

Arkiv-specific detail

  • Inspect decoded operations, entity links, attributes, expiry changes, and ownership changes.
  • View payload size, content type, payload-reference metadata, and signer-verification status.
  • See payload-provider payment breakdowns and provider links when the data is available.
In practiceUseful for “did it succeed?”, “what changed?”, “what did it cost?”, and “which entity should I inspect next?”

Source: TransactionView.tsx · arkivOperations.ts

Open this view ↗
Presenter. Show the operation list after the fee summary. Reference verification can report verified, invalid, or untrusted signer. Provider payments require the corresponding payment information. The explorer shows metadata and payload sizes; it does not store or expose entity payload bytes as a general browsing feature.
06 / EntitiesProduct tourStandard access

Read an entity’s lifecycle.

Open an entity key to trace its creation and the operations that followed.

Entity

Entity summary

  • Entity key, latest known lifecycle state, owner information, content type, and payload size.
  • Creation block / date, last activity, and available expiry information.
  • Genesis details and original attributes when the entity was imported from a seeded chain.
History

Operation history

  • Follow create, update, ownership, expiry, and delete operations in time order.
  • Inspect attribute changes and jump to the originating transaction or block.
  • See how many operations exist and when the displayed history is truncated.
In practiceUse Entity for the history of one key; use Data to search and compare entity state across many keys.

Source: EntityView.tsx · server.ts

Presenter. The default history slice contains the most recent 100 operations. If creation is outside the slice, the API can still return the first operation for the creation summary. A lifecycle label is derived from the latest stored operation; it is not a guarantee of present-time liveness. Data queries evaluate liveness at their query block.
07 / Data queriesProduct tourStandard access

Ask questions about entity state.

The experimental Data page searches entities by owner, key, built-in fields, and typed attributes.

Query editor

Build and run a query

  • Paste an entity key or owner address, or write a typed expression such as status = str('active').
  • Use syntax highlighting, completions, copyable examples, and query-language documentation.
  • Run or cancel a query, clear the editor, select page size, and copy a query permalink.
  • Recall the last 50 queries and paused drafts saved in this browser; load, copy, edit, or delete history entries.
Standard-access sources

Choose the data source

  • Experimental index: query the explorer’s indexed entity state.
  • Custom node: enter your own RPC URL and check its connection / capabilities.
  • See index availability and coverage information; errors identify invalid query positions or unavailable data.
In practiceThe Data page is explicitly experimental. A query’s reported block tells you which state the results describe.

Source: DataView.tsx · QueryEditor.tsx · dataQuery.ts

Open this view ↗
Presenter. Query history is local to this browser; loading a saved query places it in the editor without running it. Standard access offers the experimental index and a custom node. The deployment’s protected upstream and the comparison mode belong to the administrator section later. Custom-node availability depends on that node and browser CORS. Do not present the index as a live-node replacement for every method.

  • Click an attribute to copy its ready-to-paste query condition; copy identifiers and open entity history.
  • Show loaded entities estimated to expire within the next 24 hours.
In practice“Expiring soon” filters the results already loaded. Continue paging to examine more matches.

09 / Charts & rangesProduct tourStandard access

Explore changes across time and block windows.

Use Charts for patterns and Ranges for the corresponding aggregate values.

Charts

History charts

  • Select fee, priority-fee, gas, data-size, reward, burn, transaction, and available batcher series.
  • Switch the horizontal axis between dates and blocks; change resolution and point count.
  • Move backward / forward, jump to latest, inspect a selected point, and open its block window.
  • Copy the configured chart link or open a chart-only fullscreen view.
Ranges

Aggregated range table

  • Choose a supported block-window size and filter by block or date bounds.
  • Compare totals, averages, minima, and maxima for the selected window.
  • Show / hide metric columns by group and restore the full column set.
  • Set the row limit, clear filters, and copy the filtered view’s link.
In practiceStart with a trend in Charts, then use Ranges or a block detail page to inspect the values behind it.

10 / Senders & activityProduct tourStandard access

See who is driving network activity.

Sender totals give the longer view. Activity highlights the wallets doing work now.

Senders

Sender activity

  • Address-level transaction-count indicator, total gas, and fees spent.
  • Average gas / fee and first / last observed transaction block and date.
  • Open an address’s transactions or jump into its recent activity chart.
Activity

Recent activity

  • Wallet leaderboards for 5 min, 20 min, 1 hour, 6 hours, or 24 hours.
  • Compare transaction volume, gas use, and fees; recognize wallets by labels and identicons.
  • Open a wallet’s per-minute activity, switch metric / time window, change address, and refresh.
In practiceUse Senders to investigate sustained usage and Activity to find the source of a recent traffic burst.

Share a view and keep your preferences.

Display and sharing

13 / HealthProduct tourAdministrator

See whether the explorer is keeping up.

Administrator access · Health combines ingestion status, service details, and request metrics.

Health overview

Freshness and capacity

  • Sync state, scanner progress, observed chain head, head lag, and catch-up information.
  • Last block age, backfill progress, server / browser time, build commit, and build date.
  • Database / table sizes, index sizes, activity-cache status, and retained history bounds.
Server metrics

Traffic and diagnostics

  • Requests and errors by route, mean response time, database time, and response bytes.
  • JSON-RPC calls by method, endpoint, and answering source.
  • Cache hit rates / occupancy, memory and uptime, manual refresh, and raw metric output.
In practiceUse Health to separate a quiet chain, a delayed scanner, and a slow API. The page also identifies the running backend build.

Source: HealthView.tsx · ServerMetricsPanel.tsx · navigation.ts

Open this view ↗
Presenter. First sign in as an administrator and enable Admin mode. Health is an administrator-only UI view, even though basic health / sync data also has public API surfaces. Most counters are since process start. The metrics panel reports means, so do not describe its table as a percentile dashboard.

15 / Baseload scenariosProduct tourAdministrator

Generate the workload you want to study.

Baseload runs wallet-backed workers that create real Arkiv transactions using one of five behavior patterns.

Worker behaviorWhat it doesUse it to study
Creates onlyContinually create entities.Ingestion and entity-growth traffic.
Creates + updatesMaintain a pool; update entities and refresh TTL.Repeated writes to existing entities.
Creates + ownership changeCreate entities and transfer ownership.Ownership transitions and resulting state.
Time bombTarget a synchronized expiry moment.A concentrated expiration event.
Creates + updates + deletesCycle entities through their lifecycle.Churn and cleanup behavior.
In practiceThese are active workloads. Workers submit transactions and spend their configured wallets’ funds.

Source: baseloadConfig.ts · BaseloadView.tsx · baseloadRuntime.ts

Open this view ↗
Presenter. Explain the five scenarios without starting one during the presentation. This is a load-generation product feature with real network effects. The backend must have its node and wallet configuration available. “Use it to study” describes the intended experiment, not a built-in benchmark report.
16 / Baseload controlsProduct tourAdministrator

Control volume, cost, and timing.

Configure each worker’s identity, transaction shape, and run schedule from the editor.

Worker setup

Volume and cost

  • Choose a worker name, wallet, and behavior.
  • Set operations per minute, entities per request, and maximum gas price.
  • Set payload bytes, string / numeric attribute counts, and entity TTL.
  • Configure a pool size or synchronized-expiry offset for the relevant behavior.
When it runs

Run window and schedule

  • Choose a start block, optional end block, and optional duration.
  • Set active daily hours in UTC and active minutes within each hour.
  • Review the schedule description and validation before applying changes.
  • Use projected hourly / minute traffic charts to review expected transaction and payload volume.
In practiceA fee cap can leave a worker outpriced; a schedule can leave it waiting. Both states are visible in the fleet.

Source: BaseloadView.tsx · baseloadSchedule.ts · baseloadProjection.ts

Open this view ↗
Presenter. The schedule supports daily windows and minute ranges that can cross boundaries. The editor validates the configuration and distinguishes unsaved edits from applied settings. Projected traffic is calculated from worker configuration; it is not a guarantee of realized throughput or costs.
17 / Fleet managementProduct tourAdministrator

Operate workers and reuse configurations.

Keep a repeatable load setup and watch the fleet’s actual state while it runs.

Workers + status

Operate the live fleet

  • Add a worker, apply edits, revert an unsaved draft, or delete a worker.

Configuration library

Save and transfer setups

  • Save the current fleet under a name; refresh, load, or delete saved configurations.
  • Download / load a full fleet as JSON.
  • Export one worker or import a worker into the editor for review before adding it.
In practiceApplied live configuration survives backend restarts. Loading a saved fleet applies that setup to the live runtime.
